经营人员可通过对话上传图片或文件、查询和分析经营数据，获得文字答复或报告文件，也可设置定时任务自动生成报告，并按权限向指定人员或目录分发成果。

DDD 领域划分

限界上下文管理的业务对象负责的规则与跨域接口DeepClaw 实现落点
经营分析
核心		分析会话、分析结果、采用的指标口径与统计期间实时问答和后台任务共用分析入口。分析结果关联 run_id、采用的业务口径和文件版本，便于追溯。复用 AG-UI、Agent Runtime 和 RunStore，新增经营分析 Agent 与业务数据查询适配。
自动化任务
支撑		任务配置、试跑草稿、运行批次及执行通知试跑结果绑定草稿版本。到期领取任务后，按批次快照调用分析入口。重试沿用该批的统计期间。通过 Run ID 和文件版本关联结果。复用 CronMiddleware、ScheduleStore 和 schedule_worker()。扩展任务草稿、试跑、批次和重试。
文件知识库
支撑		文件、文件版本、收藏与保留策略统一登记上传文件和分析产物。预览、下载或问答读取前，结合文件归属、角色权限和共享动作授权执行校验。读写和解析由文件服务负责。复用 FileService、FileMiddleware 和 ObjectStorage，补文件版本及共享访问校验。
文件分发
支撑		目录、发布记录、共享授权和收件记录发布绑定文件版本。分发上下文校验发起人的发布权限，并提供共享授权的查询、撤销和过期判断。收件记录由分发上下文维护。新增文件分发应用服务和授权查询，接入现有文件接口与角色管理。
身份与访问控制
通用		账号、角色与功能权限策略提供可信账号和角色权限判定。各业务上下文结合自身数据判定资源归属和允许的动作。复用 DeepClaw Auth 与 Casbin RBAC。

首版采用模块化单体。HTTP 路由与 Agent 工具进入各自的应用服务，由业务模块执行规则并写入负责的数据。跨模块调用使用应用服务和稳定 ID，表可共用 SQLite 或 PostgreSQL。OpenResty、模型客户端、SQLModel 和对象存储归入基础设施。

FileMiddleware 工具

工具能力为什么这么设计
list_files按账号列出上传和生成件。offset / limit 分页，默认 20，单页最多 50，返回 next_offset。模型可找到旧文件和稳定 ID，文件量增大时维持固定的查询规模。
inspect_file查看总行数、Sheet 名称、PDF 页数及无文字页。先了解结构，再确定读哪张表或哪段。扫描页可及时转到视觉流程。
read_file
read_chat_file		start_line 从 1 开始，默认 100 行，最多 200。支持指定 Sheet 和列字母，返回行号、PDF 页码或表格坐标及 next_start_line。单行和整体返回有字符预算，超长项标记截断。模型可自行续读和准确引用。解析只在入库时做一次，每轮工具调用仅返回所需窗口。
grep_file字面搜索为默认，支持正则、忽略大小写、限制 Sheet 和游标续查。默认 30 个命中，最多 100，返回命中的页码、行号或单元格。大文件先定位再读取命中上下文。搜索与分页共用一套坐标。
write_file
write_chat_file		Markdown 接收 content，Excel 接收多 Sheet 的 sheets 与有类型的单元格。生成新文件并返回 file_id 和 download_url。模型提交结构化数据，服务端生成文件并统一落库。相同的文件卡片可用于聊天、成果页和后续分发。
export_file从已有 Markdown 生成独立 DOCX，需要源文件读取和新文件写入权限。一份已经确认的报告正文可重复导出，原 Markdown 与 Word 各自拥有稳定 ID。

为什么采用 FileMiddleware

比较维度通用文件系统 + Python 执行DeepClaw FileMiddleware
模型如何操作模型通过 read、grep、write 操作工作区路径，遇到 PDF、Word 或 Excel 时可编写 Python 脚本调用相应格式库。模型传入 file_id 和结构化参数，由 FileService 统一解析或生成文件。搜索和分页读取共用行号、页码和 Sheet 坐标。
安全隔离开放模型生成的代码时，需要配置隔离执行环境，限制文件挂载、网络、凭据访问和资源用量，同时管理工作区的创建与回收。这组工具只开放约定的文件操作。服务端使用可信账号校验角色权限和文件归属，根据文件 ID 定位对象，文件问答和报告生成可直接通过文件服务完成。
交付与维护需要维护解释器、格式库与沙箱运行环境。工作区产物要进入聊天、文件知识库或分发流程时，还需要上传和登记。服务端集中维护格式适配与解析缓存，复用 DeepClaw 的数据库和对象存储。上传件与生成件都直接登记到文件知识库，聊天与后续分发可引用同一个文件 ID。
适用场景适合临时脚本、复杂计算、自定义转换，以及需要模型自由组合库的任务。适合格式和操作已知的文档问答、报表生成与成果交付。新增格式或导出样式时，由服务端扩展对应适配。

经营分析的常用流程是读取用户材料、按页或按行定位依据、生成报告并登记成果。采用 FileMiddleware 后，这条流程可复用现有文件服务，省去为常规文件操作部署和维护模型脚本执行环境的成本。

原件Local 或 MinIO 保存私有对象，媒体字节由接口读写。鉴权下载，Markdown 源格式可读原件。
解析缓存统一 JSON。PDF 存文字行与页码，Excel 按工作表存原行号与列坐标，TXT / MD / DOCX 存文本行。预览、inspect_file、read_file、grep_file 使用相同定位。Markdown 默认整份渲染。

图片与定时产物拟增加图片类型与独立预览路径，用户主动保存后按同一元数据体系登记。定时任务当前使用独立产物存储路径，改造后由调度执行器调用成果登记服务。图片和定时文件都得到文件 ID，供成果列表、执行历史及分发引用。

CronMiddleware 工具

CronMiddleware 注册 cron_tool，Agent 通过 action 参数选择以下操作。

工具能力为什么这么设计
cron_tool
add		在 changes 中传入名称、交付内容与触发方式。校验后保存任务，返回任务 ID、配置及下次执行时间。聊天和网页共用配置校验。Agent 可以把已保存的执行时间反馈给用户，后台 Worker 到期执行。
cron_tool
list		查询当前账号的任务，包括任务 ID、配置和下次执行时间。调用需要任务读权限。Agent 可先根据名称找到任务并确认 ID，再对指定任务修改或删除。查询权限可独立授予。
cron_tool
update		传入 job_id 和 changes，合并旧配置后重新校验。enabled 支持暂停和恢复。切换触发方式时，旧触发字段设为 null。局部修改保留其他配置。暂停可以保留任务设置，恢复后可以继续使用。
cron_tool
remove		传入 job_id，删除当前账号下的目标任务，停止后续调度。任务 ID 明确删除目标，服务端结合当前账号校验归属，避免误删同名任务。
调度规则与异常处理
原型动作后端行为
对话新建、页面新建与修改自动化页「新建定时任务」和聊天入口进入同一草稿流程。Agent 只提交结构化草稿变更。试跑成功记录绑定草稿版本、完整要求、引用版本和输出配置。草稿变更使旧试跑结果失效，正式保存校验版本与最新权限。编辑期间已发布配置照常执行，正式保存仅影响后续批次。
周期、时间与统计期间界面显示每日、工作日、每周、每月及下次执行，服务端沿用 DeepClaw 一次性、按秒间隔、五段或六段 Cron 与 IANA 时区。工作日按周一至周五，有节假日规则时单独接日历。将计划执行时间按任务时区解析为当天、前日或上月等业务窗口，批次存下实际采用的范围。手动重试复用原批次窗口。
后台执行与暂停恢复复用数据库领取、租约和异步调度，将现有 deliver() 中的单次模型调用改接经营分析 Run。定时和立即执行共用队列，每批次生成独立会话。暂停阻止后续自动领取，已领取批次按快照执行，恢复时重新计算下一次触发。建议保留 DeepClaw 的停机补执行一次策略。后台执行有独立并发配额，并与实时聊天共享模型限流预算。
执行历史与失败重试结果按批次聚合，显示触发时间、实际统计期间、状态、尝试、文件及会话入口。失败时在该执行会话确认重试，同批新增尝试且复用原任务版本。调度批次键采用任务 ID 和计划时间，立即执行使用请求幂等键。删除任务采用历史可见的软删除，运行、成果和会话分别管理。
站内通知批次结束后生成一条含任务名称、完成时间和状态的未读通知。铃铛列表展示摘要，点开查看文本、会话与文件。待处理的文件分发投递与成果生成分开记录。

文件知识库如何共享

实现点数据与行为
个人临时共享拟增 file_grants，保存文件及版本、授权发起人、subject_type、subject_id、允许动作、生效和到期时间、撤销时间。选定用户 ID，接收人可预览，可按配置下载。问答引用独立授权，默认关闭，启用后可通过 @ 及文件工具读取。
目录长期分发拟增 file_directories 和发布映射。一个主目录可有多个引用位，数据库只记录关系。组织与角色从认证系统取实时成员，目录按父级规则继承。发布同时校验发起人拥有文件和目标目录的发布权限。
统一鉴权保留所有者专用的修改、删除、再分发入口。为读取增加 get_accessible_file(actor, file_id, action) 和可访问列表。HTTP 与 Agent 工具共用该判断，预览授权只开放页面预览，工具读取必须允许「问答引用」。工具上下文只信任运行时注入账号。同一用户命中多个授权时按有效动作合并。
收件与追踪拟增分发投递记录和 read_at，最近 24 小时的新到或更新在「最近接收」，阅读后进入历史。「我发出的」聚合收件范围与时效。同一文件同一业务日的更新提示可合并，站内和外部渠道按幂等键投递。
撤销、过期与清理撤销或过期后，实时重新计算有效授权，列表与聊天卡片更新状态，再次打开或工具读取按新权限处理。单独保留收件审计。历史回答的内容按会话保留策略管理。清理排除有有效授权或执行任务引用的文件。
水印与文件权限接收人获准下载时，经后端返回带账号和时间标识的派生文件。原件键和解析缓存保持私有。角色管理同步补入共享、目录发布和审计权限，文件访问仍需通过具体资源授权。
